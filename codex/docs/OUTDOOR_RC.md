# 야외 RC 기록·학습·GPS 순환 주행

아두이노는 현재 펌웨어를 유지합니다. 2026-11-03 젯슨에 반영하고 빌드했습니다. 이후 소스를 수정하면 `cb`로 다시 빌드하세요.

## 시작

```bash
ros2 run isv_water_trials tank_session start sensors
```

브링업과 함께 GPS 위치·선수 방향·이동 경로, RC·자율주행 기록과 모델 학습이 켜집니다. 수조 매핑은 필요 없습니다. 기존 대시보드 프로그램으로 연결한 뒤 `http://127.0.0.1:8765/`를 여세요. 배경 지도를 못 불러오면 미터 격자 위에서 같은 기능을 사용할 수 있습니다.

RC·자율주행 중 좌우 적용 명령, 전진·횡방향 속도와 회전속도를 기록합니다. 그래프는 **실측 실선 / 예측 점선**입니다. 좌현은 청록, 우현은 주황, 전진은 파랑, 횡방향은 자홍, 회전은 노랑으로 구분합니다. 지도 화살표는 북쪽 0°, 시계방향 기준입니다. 보라 점선은 현재 출력을 유지한다고 가정한 3초 예측, 주황 점선은 실제 주행에서 선택한 회피 계획입니다.

지도에 마우스를 올리면 해당 지점의 위도·경도가 표시됩니다. 지도를 클릭하면 `위도, 경도`를 복사합니다. 드래그는 지도 이동만 하며, 지점 추가 모드에서는 클릭한 위치를 경로에도 추가합니다.

## 일시정지·재개

대시보드의 **학습 중지**는 모델 갱신을 멈춥니다. 기록·현재 위치·방향·경로·예측 비교는 유지합니다. **학습 재개**부터 새 구간을 학습에 추가합니다. 외부 EMO의 전원 차단 상태는 아두이노에서 읽을 수 없으므로, EMO를 누른 채 RC 입력을 시험할 때는 학습을 일시정지하세요.

센서를 다시 켜려면 다음 순서로 진행합니다.

```bash
ros2 run isv_water_trials outdoor_ctl pause
ros2 run isv_water_trials tank_session stop sensors
ros2 run isv_water_trials tank_session start sensors
ros2 run isv_water_trials outdoor_ctl resume
```

기존 기록·모델은 보존하고 재시작 전후를 다른 구간으로 처리합니다. 재시작은 GPS 오차를 제거하는 기능이 아닙니다. 유효한 위치·속도·IMU 시각이 맞는 구간부터 다시 사용합니다. **누적 경로 초기화**는 화면 이동 경로만 지우며 학습 자료·저장 모델·지정한 목적지는 유지합니다.

## 모델과 검증

화면에는 **학습 모델 하나**와 **검증에 적용한 모델 하나**를 표시합니다. RC·자율주행 기록과 중간 모델은 백그라운드에 계속 저장하고, 재시작하면 마지막 상태를 자동으로 이어갑니다. **현재 모델 적용**은 현재 학습 모델을 검증 주행용으로 복사합니다. 학습은 계속되며, 검증 모델은 다시 적용할 때까지 유지됩니다. 주행 중 교체하려면 먼저 주행을 정지합니다.

30초마다 전체·최근·입력별 균형·강건 표본, 선형·비선형 수식, 0~1.6초 지연 후보와 직전 모델을 비교합니다. 직전 모델을 평가한 이후의 새 RC·자율주행 기록을 선택·평가에 사용하며, 연속 기록 약 60초 이상이 모여야 다시 비교할 수 있습니다. 그동안 현재 모델을 유지합니다. 후보 선택용 구간과 최종 평가 구간을 나눕니다. 모든 조합을 전수 탐색하는 방식은 아니며, 평가에 쓰지 않은 운항 상황의 정확도는 별도 확인이 필요합니다.

원본은 모두 보관합니다. 계산량을 제한하기 위해 최근 15,000개 표본과 과거 시간을 나눠 무작위로 고른 최대 15,000개 연속 구간 표본을 사용합니다. 센서 단절·잘못된 시각·학습 중지 구간은 계수 학습에서 제외합니다. 학습 중지는 원본 보관을 계속하며, 재개 이후 유효한 RC·자율주행 자료부터 다시 반영합니다. 임의의 외부 파일을 폴더에 넣는 가져오기는 아직 지원하지 않습니다.

강건 후보는 학습 구간에서 큰 잔차의 영향을 줄입니다. 모든 후보와 직전 모델은 같은 별도 구간에서 비교하며, 누적 데이터가 많아도 새 환경의 정확도는 실제 검증으로 확인합니다.

모델 이름은 `전체·비선형`, `최근·선형`처럼 후보 구성으로 표시합니다. 현재 모델 적용 옆에서 학습 최적 후보와 검증 적용 모델의 평균속도·최저 오차 속도 구간(m/s), 지연시간, 사용 표본을 비교합니다. 아래에는 누적 기록 구간 수와 전체 후보 목록을 표시합니다. 속도 구간은 겹치지 않는 3초 검증 5회 이상에서 2초 예측 오차로 비교하며, 표본이 부족하면 자료 부족으로 표시합니다.

이 모델은 좌우 출력과 과거 상태로 전진·횡방향 속도·회전속도를 예측합니다. 질량 25kg, 길이 1.1m, 폭 0.5m, 추진기 간격 0.32m는 알려진 선체값입니다. 회귀 계수를 실제 추력·저항·부가질량으로 단정하지 않습니다.

## 목적지와 순환 주행

1. **지점 추가**를 켜고 GPS 지도에서 목적지를 순서대로 찍습니다. 2~100개를 지원합니다.
2. **경로 저장**을 누릅니다. 지점은 젯슨에 저장됩니다.
3. 검증을 통과한 모델에 **현재 모델 적용**을 누르고 출력 상한을 지정한 뒤 **순환 주행 시작**을 누릅니다.

순서는 `1 → 2 → … → 마지막 → 1 → 2 → …`입니다. 경로를 수정하면 현재 주행을 중립으로 정지하며 새 경로 저장 후 다시 시작합니다. 도착 반경 기본값은 2m, 지점 간 거리는 5~200m입니다. 라이다는 기존 `/scan` 한 층을 사용합니다. 출력 20%는 좌우 명령의 **상한**이며 선회·감속·장애물 회피 시 각각 조정합니다.

```bash
# 화면 대신 터미널에서 조작
ros2 run isv_water_trials outdoor_ctl apply_model
ros2 run isv_water_trials outdoor_ctl start --percent 20
ros2 run isv_water_trials outdoor_ctl stop
ros2 run isv_water_trials outdoor_ctl status

# 모든 추진 시험에 정지 요청
ros2 run isv_water_trials stop_thrusters

# 브링업과 기록 종료
ros2 run isv_water_trials tank_session stop sensors
```

CODEX `SamplingNavigator`의 후보 생성·경로 평가·가중 후보 재검사를 재사용합니다. 물리 시뮬레이터 대신 학습 모델과 출력 역산을 연결하고 선체 크기에 맞춰 충돌을 검사합니다. A* 경로는 충돌 여유를 확인하며 모서리를 곡선으로 연결합니다. 평활화가 어려운 구간은 원래 안내 경로를 사용하고 예측 선체 충돌 검사를 유지합니다. 라이다의 연속 관측으로 장애물 속도·방향을 추정하며, 등속 이동을 가정한 3초 미래 위치와 시간에 따라 커지는 불확실성을 회피 계산에 반영합니다. GPS·IMU 오차나 물체의 급회전·가속, 가림은 추적 오차를 만들 수 있습니다. 도킹 전용 제어는 별도입니다.

일반 경로가 막히면 계산 시간이 남는 범위에서 최대 20% 출력으로 선회·역추진 후보를 다시 검사합니다. 이때 정적 장애물 여유는 기본 0.1m까지 줄이며, 움직이는 장애물 여유는 유지합니다. 선체가 겹치거나 관측 범위에서 벗어나는 후보는 실행하지 않습니다. 가능한 후보가 없으면 출력을 중립으로 두고 재탐색하며 노드는 유지됩니다.

`scan_range_m: 0`은 `/scan` 메시지의 `range_max`를 따릅니다. 숫자를 지정하면 그 거리로 제한합니다. 센서 드라이버가 잘라낸 데이터는 복원할 수 없습니다. 먼 관측도 받아들이되 A*는 주변 40×40m·0.4m 격자를 사용합니다. 경로를 최대 0.6초 재사용하되 새 장애물이 있으면 다시 검사하고, 장애물 점은 같은 격자에서 보수적으로 묶어 계산량을 줄입니다. 추적은 최대 48개이며 짧은 가림은 1초까지 예측합니다.

지도 레이어는 현재 히트포인트·누적 관측·A* 원본·평활 경로·회피 예측·현재 출력 예측·장애물 예측·이동 경로·현재 위치·목적지를 각각 켜고 끌 수 있습니다. 선택은 브라우저에 저장하며 표시를 꺼도 센서 기록과 주행 계산은 유지합니다. 라이다 점은 GPS·IMU 좌표에 겹쳐 표시하며, 위치 오차를 함께 고치는 SLAM은 별도입니다. 누적 관측은 최근 20초·최대 4,000개 격자로 제한하고 새 관측에서 빈 공간으로 확인된 점은 지웁니다. 원본·평활·회피 경로와 이동 장애물 예측은 주행 중 계산 결과를 표시합니다.

SSH나 화면이 끊겨도 젯슨 프로세스는 유지됩니다. 센서·추진기 연결이 끊기면 주행 프로세스는 대기하고 출력을 중립으로 보냅니다. 다시 유효한 데이터가 들어오면 실행 중인 주행을 이어갑니다. 젯슨 전원 재시작 후에는 기록·선택 모델을 복원하며, 추진은 **순환 주행 시작**으로 다시 켭니다.

## 저장 위치와 현장 확인

- `~/water_trials/outdoor/observations.sqlite3`: 시각·실제 출력·RC/AUTO·응답·구간 기록. 약 1초마다 디스크 반영.
- `~/water_trials/outdoor/models/YYYY-MM-DD/`: 한국 날짜별 자동 저장 모델. 검증 적용 모델은 별도로 유지하며 같은 ID의 내용을 보존합니다.
- `~/water_trials/outdoor/route.json`: 위도·경도 목적지 목록.
- `~/water_trials/outdoor/bags/`: GPS 위치·속도, IMU, 라이다, 추진 상태 원본. 60초 단위 분할.
- `/outdoor/status`, `/outdoor/command`, `/outdoor/request`: 화면 상태, 주행 명령 기록, 조작 요청.

`isv_water_trials/config/outdoor.json`이 두 설정 파일을 연결합니다. `outdoor_learning.json`에는 센서·추진 보정, 선체값, 학습 주기를 두고 `outdoor_navigation.json`에는 라이다 관측, 장애물 여유, 도착 반경, 출력 상한, 계산 제한을 둡니다. 주행 설정과 학습 주기만 바꾸면 기존 모델·기록을 재사용합니다. 센서·선체·추진 보정이나 예측 시간 간격이 달라지면 학습 설정을 구분합니다. 예전 모델은 함께 저장된 `configs`의 설정이 일치할 때 불러옵니다. 설정 파일을 편집한 뒤 `cb`와 센서 세션 재시작으로 반영합니다. 기존의 단일 설정 파일도 읽을 수 있습니다.

 오늘 사용한 ROS 라이다 축 `+X=선수, +Y=좌현`과 추가 회전 0°를 유지합니다. VectorNav 원시 NED 방위각은 기존 설정대로 ENU로 변환합니다. 장착을 유지하면 같은 방향 설정을 재사용합니다. GPS 안테나·라이다 위치 오프셋 기본값은 0m이며, 회전 중 안테나 위치와 선체 중심의 속도 차이를 정밀하게 다룰 때 실측값을 적용합니다. 학습 관련 보정이 달라지면 학습 자료와 모델을 구분해 사용합니다.

젯슨 ROS 실행, 실제 GNSS 주기·정확도, IMU 방향, 실제 추진 및 회피 성능은 현장에서 확인할 항목입니다.

## 가상 장애물 모델 시험

실시간 학습과 예측 비교는 계속됩니다. **현재 모델 적용**을 누른 시점의 모델로 주행하며, 이후 학습 결과는 다음 적용까지 주행 모델을 바꾸지 않습니다. 1·2·3초 예측 평가는 그동안 실제로 바뀐 명령을 사용합니다.

1. 운항 가능한 수역을 확인한 뒤 **시험구역 지정**을 누르고 지도에서 가장자리를 순서대로 3~12점 찍습니다. 들어간 모서리 없이 볼록한 구역으로 지정하며 현재 배도 안쪽에 둡니다.
2. **모델 시험 시작**을 누르면 현재 관측 안에서 왕복 목표 두 곳과 가상 장애물 한 개를 생성합니다. 출력은 화면에 지정한 상한을 사용하며 기본값은 20%입니다. 적용 모델의 학습 출력 범위를 함께 확인합니다.
3. 노랑 점선으로 시험구역과 가상 장애물을 표시합니다. 실제 라이다 장애물과 시험구역 경계도 경로 계산에 함께 적용합니다. GPS·IMU는 배 상태, 라이다는 실제 장애물·관측 거리 판단에 사용합니다.
4. **시험 정지** 또는 기존 **주행 정지**로 종료합니다. 시험 전의 일반 경로가 복구됩니다.

가상 장애물은 센서 원본에 섞지 않고 주행 제약으로만 추가합니다. 라이다 무응답만으로 가항 수역을 판정할 수 없으므로, 시험구역은 직접 확인한 수역에 지정합니다. 경로가 없거나 센서 상태가 나빠지면 중립으로 대기합니다.

**계획 대비 위치 오차**는 과거에 생성한 예측 경로의 해당 시각 위치와 나중에 측정한 위치를 비교합니다. 재계획·제어 지연·외란의 영향도 포함되므로, 실제 명령으로 평가하는 모델 자체의 응답 오차와 구분해 봅니다. RC 조종 중에는 이 주행 시험 오차를 집계하지 않습니다. 시험 조건·예측 경로·오차는 기존 `observations.sqlite3`의 이벤트 기록에 누적합니다.

2026-11-03 확인: PC 검사 114개 중 94개 통과·ROS/POSIX 환경이 필요한 20개 생략, 대시보드 검사 118개 통과. 젯슨에서는 야외 기능 검사 62개와 두 패키지 빌드, 별도 ROS 도메인의 기록 노드→대시보드 수신 연결을 확인했습니다. 실제 센서 수신·계산 주기·수상 주행은 현장 확인 항목입니다.
