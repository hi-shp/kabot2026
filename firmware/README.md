# Arduino UNO R3 추진기 제어

최신 사용자 배선 기준: RC 좌현 D2 → ESC 좌현 D9, RC 우현 D3 → ESC 우현 D10, RC/AUTO 전환 PWM D4. 좌우는 독립 제어하며 혼합 계산을 하지 않습니다. 기존 D9/D10 출력 극성을 유지하고 반전하지 않습니다. 양쪽 모두 RC 입력 1000~2000 µs, 중립 1500 µs, 중립 허용폭 ±40 µs로 동일합니다. 우현 스틱에 자동 중립 복귀 기능이 없다는 사용자 설명에 따라 측정 당시 우현 위치를 별도 중립으로 보정하지 않습니다.

RC 출력 변화량은 기존의 1/5입니다(예: 입력 1700 → 출력 1540 µs). 속도 누적은 없습니다. 각 채널은 독립적으로 ≥1900 µs 또는 ≤1100 µs를 150 ms 유지하면 해당 출력만 1900 µs 또는 1100 µs가 됩니다. 입력 끝점에 100 µs의 여유를 두어 정확히 1000/2000에 도달하지 못해도 동작합니다. 한쪽이 끝 영역에서 벗어나면 그쪽만 즉시 1/5 응답으로 복귀하고 다른 쪽에는 영향을 주지 않습니다. 중립에서는 1500 µs입니다. 실제 추력이나 회전수의 선형 비율을 뜻하지 않습니다.

D4가 1700 µs 초과이면 RC, 1300 µs 미만이면 AUTO입니다. 900~2100 µs 범위를 벗어나거나 1300~1700 µs 중간값, 신호 단절(100 ms)이면 중립으로 억제합니다. RC→AUTO 전환 즉시 양쪽 PWM을 1500 µs로 만들고 끝점 판정과 무장을 초기화합니다. 새 무장과 새 명령을 받기 전에는 중립입니다. PWM 변경은 다음 서보 펄스 주기에 반영되며 관성에 의한 즉각적인 물리 정지를 보장하지 않습니다. 물리 EMO는 사용자가 설명한 외부 전원 차단 회로이며 UNO 입력에는 연결하지 않습니다. 펌웨어는 물리 EMO 상태를 확인했다고 보고하지 않습니다.

EEPROM도 젯슨 백업 폴더에 보관했습니다. 백업 바이너리는 Git에 올리지 않았습니다.

수정 직전 보드 플래시는 Windows COM7에서 두 번 읽어 `arduino-before-direct-channels`에 별도 보관했습니다. 오늘 최초 원본 백업도 보존합니다. 최종 UNO 펌웨어는 9294바이트이며 업로드 후 전체 플래시 대조 검증을 통과했습니다. 제어·끝점·모드·통신 단위 검사는 ASan/UBSan과 잘못된 프레임 2만 건을 포함해 통과했습니다.

모터 전원이 분리된 실제 보드에서 USB 연속 수신, 좌현만 최대·우현 중립, 우현만 최대·좌현 중립, 작은 입력의 완화된 응답, RC→AUTO 시 1500/1500 µs·무장 해제를 확인했습니다. 입력 1988 µs도 출력 1900 µs로 인식했습니다. AUTO에서 1540/1540 µs 명령 50쌍을 5.06초간 수락했고 GPIO 펄스도 관측했습니다. 명령 전송을 멈춘 뒤 0.7초 시점에 1500/1500 µs·무장 해제를 확인했으며 마지막 해제 응답도 받았습니다. 내부 GPIO 펄스 관측은 외부 계측기 측정과 구분하며 실제 추진기 회전은 확인하지 않았습니다.

ROS 브리지는 시작할 때 자율운항 무장 해제 명령만 보냅니다. AUTO 위치에서 조종기 중립을 확인한 뒤 `/actuators/arm`에 `true`를 보내야 명령을 받으며, `false`는 자율운항 명령을 해제합니다. 한쪽 추진기 서비스 호출만으로는 출력하지 않고, 좌우 서비스의 동시 요청을 한 프레임으로 묶습니다. 명령 유효 범위는 좌우 각각 1400~1600 µs, MCU 명령 만료는 400 ms입니다. 자율운항 경로 계획과 MPC는 젯슨에서 실행합니다.
