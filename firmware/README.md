# Arduino UNO R3 추진기 제어

최신 사용자 배선 기준: RC 좌현 D2 → ESC 좌현 D9, RC 우현 D3 → ESC 우현 D10, RC/AUTO 전환 PWM D4. 좌우는 독립 제어하며 혼합 계산을 하지 않습니다. 기존 D9/D10 출력 극성을 유지하고 반전하지 않습니다. 양쪽 모두 RC 입력 1000~2000 µs, 중립 1500 µs, 중립 허용폭 ±40 µs로 동일합니다. 우현 스틱에 자동 중립 복귀 기능이 없다는 사용자 설명에 따라 측정 당시 우현 위치를 별도 중립으로 보정하지 않습니다.

RC 응답은 좌우 독립적인 2차 곡선입니다. `q=clamp((|입력-1500|-40)/360, 0, 1)`, `출력=1500±400q²`를 정수 µs로 반올림합니다. 중립 ±40 µs는 출력 1500 µs이며, 입력 1100 이하/1900 이상에서는 출력 1100/1900 µs입니다. 끝점 오차를 허용하면서 그 직전까지 곡선으로 연결하므로 별도의 최대 출력 점프·150 ms 전환 대기·속도 누적이 없습니다. 실제 추력이나 회전수의 제곱 관계를 뜻하지 않습니다.

D4가 1700 µs 초과이면 RC, 1300 µs 미만이면 AUTO입니다. 900~2100 µs 범위를 벗어나거나 1300~1700 µs 중간값, 신호 단절(100 ms)이면 중립으로 억제합니다. RC→AUTO 전환 즉시 양쪽 PWM을 1500 µs로 만들고 무장을 해제합니다. 새 무장과 새 명령을 받기 전에는 중립입니다. PWM 변경은 다음 서보 펄스 주기에 반영되며 관성에 의한 즉각적인 물리 정지를 보장하지 않습니다. 물리 EMO는 사용자가 설명한 외부 전원 차단 회로이며 UNO 입력에는 연결하지 않습니다. 펌웨어는 물리 EMO 상태를 확인했다고 보고하지 않습니다.

기존 플래시는 업로드 전에 젯슨의 `/home/isv/code_backups/arduino-uno-before-autonomy-20261029/`에 두 번 읽어 동일한 바이너리로 보관했습니다. 원본 플래시 SHA-256: `493c1b59f0269dc2387b39d5693cd5b79eb6be63a2181e03d82696af50f2b346`. 로컬 사본은 `C:\Users\Park\Documents\JetsonWaterTrial-20261029\arduino-original-backup\flash_read1.bin`입니다. EEPROM도 젯슨 백업 폴더에 보관했습니다. 백업 바이너리는 Git에 올리지 않았습니다.

오늘 최초 원본 백업과 `arduino-before-direct-channels`, 2차 곡선 변경 전의 `arduino-before-quadratic` 백업을 모두 보존합니다. 단위 검사는 입력 전체 범위의 단조 증가·좌우 독립·역방향 대칭·최대 인접 변화량·모드·통신을 검사합니다.

현재 2차 곡선 버전은 9404바이트입니다. Windows COM7 업로드 후 전체 플래시 대조와 AUTO·무장 해제·중립 상태 응답을 확인했습니다. 젯슨 빌드 결과도 Windows에서 업로드한 9404바이트와 완전히 일치했습니다. ASan/UBSan 및 잘못된 프레임 2만 건 검사를 통과했습니다. 입력 900~2100 µs 전 구간에서 단조 증가·대칭을 검사했고 인접 입력 1 µs당 출력 변화는 최대 3 µs입니다. 새 곡선의 실제 추진기 회전은 시험하지 않았습니다.

직전 버전은 모터 전원이 분리된 실제 보드에서 좌우 독립 최대 출력, RC→AUTO 중립, AUTO 명령 50쌍·5.06초 수락과 명령 중단 후 중립 복귀를 확인했습니다. 내부 GPIO 펄스 관측은 외부 계측기 측정과 구분하며 실제 추진기 회전은 확인하지 않았습니다.

ROS 브리지는 시작할 때 자율운항 무장 해제 명령만 보냅니다. AUTO 위치에서 조종기 중립을 확인한 뒤 `/actuators/arm`에 `true`를 보내야 명령을 받으며, `false`는 자율운항 명령을 해제합니다. 한쪽 추진기 서비스 호출만으로는 출력하지 않고, 좌우 서비스의 동시 요청을 한 프레임으로 묶습니다. 명령 유효 범위는 좌우 각각 1400~1600 µs, MCU 명령 만료는 400 ms입니다. 자율운항 경로 계획과 MPC는 젯슨에서 실행합니다.

젯슨 소스는 `~/boat_firmware/kabot_actuator/`입니다. Arduino CLI 1.5.1, AVR core 1.8.6, Servo 1.3.0, PinChangeInterrupt 1.2.9를 사용합니다. 수정 후 다음 명령으로 빌드하며, 업로드 전에는 ESC·모터 전원을 분리하고 Arduino 브리지·시리얼 모니터를 종료합니다.

```bash
cd ~/boat_firmware
nano kabot_actuator/board_config.h  # 배선·범위. 곡선은 manual_response.h
bash jetson_upload.sh             # 검사·컴파일만
bash jetson_upload.sh --flash     # 기존 플래시 2회·EEPROM 백업 후 업로드·검증
```

USB 포트가 없거나 사용 중이거나 백업 검증이 실패하면 쓰기 전에 중단합니다. 백업은 `~/code_backups/arduino-preupload-*`에 보관합니다. CH340 USB 장치가 운영체제에서 안정적으로 인식되어야 사용할 수 있습니다. CLI 참고: https://docs.arduino.cc/arduino-cli/commands-reference/arduino-cli_compile
